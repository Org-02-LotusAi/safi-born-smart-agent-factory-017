•  Reusability: T0 → T1 → T2 pinned ancestry; trained T2 revision produces new instances without mutating previously deployed instances.
2. Foundational Template and Refinement contract
A Template is an immutable JSON Object with a unique, exact-version Parent (except T0). Skills are typed composition references, NOT additional Parents. A separate canonical Node.js implementation compiles and instantiates every Agent.
Contract element
 | Mandatory semantics
 | Template record
 | kind, id, version, parent {id, version, sha256}|null, refinement, parameterSchema, tests, knowledgeRefs, skillRefs; stored in Git; exact-release registry index.
 | Canonical resolution
 | Resolve Root → selected child. Verify hash and version of every ancestor; reject missing links, cycles, duplicate identifiers and changed same-version content.
 | Typed refinement
 | Allow ONLY addKnowledgeRefs, addSkillRefs, addConstraints, addTests, addParameterFields and additive role guidance. Policy IDs must be runtime-enforced and allowlisted; unknown operations FAIL.
 | Inheritance invariants
 | Inherited constraints/tests never disappear; field collisions FAIL; no privilege elevation. Detectable conflicts FAIL; unresolved semantic contradictions require Trainer rejection.
 | Instance schema
 | Compile admitted property definitions and required fields; seal effective result. Validate input using JSON Schema Draft 2020-12 and Ajv strict mode; semantic checks are separate.
 | Hash and provenance
 | RFC 8785 canonical JSON → SHA-256; hash excludes digest self-reference. Pin Template chain, skill/knowledge digests, runtime package SHA and model identifier in instance manifest.
 | Tool authorization
 | Effective tools = requested Template tools ∩ customer/Office grants. Training cannot change grants. Credentials never enter Templates, Git or browser JS.
 | 
Correctness boundary: JSON Schema validates structure. The compiler checks permitted refinements and inherited obligations; evaluation demonstrates bounded Agent behavior. This does NOT prove that every future LLM answer is correct.

4. Canonical JavaScript Factory — the ONLY creation path
Implement factory.mjs as the shared library/CLI; the SPA backend MUST invoke it, not duplicate its logic. The Factory API is expressed in openapi.yaml and implemented in Node.js; the browser receives no model/API secrets.
Operation
 | Exact outcome
 | compile(templateRef)
 | Validate Template meta-schema → walk exact Parent chain → enforce typed R(parent, Δ) → union inherited obligations → compute effective schema/manifest/hash.
 | instantiate(ref, config)
 | Validate structural and semantic inputs, confirm Office-granted tool list, mint permanent UUID; write immutable binding to compiled SHA/model/skills and a private customer data directory.
 | run(instance, task)
 | Execute an actual @openai/agents runtime with pinned instructions, permitted tools and source-grounded job workflow; persist run metadata and approved memory only.
 | train(ref, lesson)
 | Use the LLM to PROPOSE an allowlisted typed JSON refinement and regression test from natural-language Trainer correction; schema-check draft. Trainer approves; no self-promotion.
 | qualify(draft)
 | Re-run inherited baseline tests plus new regression; emit machine-readable individual PASS/FAIL and captured evidence. Human Trainer approval gates publication.
 | publish/deploy(ref, office)
 | Publish a digest-pinned qualified version to Git/release archive, then install its instance runtime into customer Office via authorized SSM; support restart/reuse.
 | 
Formal kernel: E(T0) = base; E(T) = R(E(parent(T)), ΔT); Constraints(T) ⊇ Constraints(parent); Tests(T) ⊇ Tests(parent). Same inputs and exact dependency versions must produce the same effective definition/hash; different Agent instances receive distinct permanent IDs.

10. Security, failure recovery and non-goals
•  Do not store API secrets in client JS, JSON Templates, Git, logs or training examples. Use Office-controlled secret mechanism; only scoped model/provider permissions. Limit network/file access to approved tools.
•  Untrusted resumes and job postings are DOCUMENT DATA. They cannot override instructions, grant access or trigger actions; reject attempts to exfiltrate files or evade approval.
•  A failed compile, qualification, explicit promotion, deployment or model call must be reported as FAIL with a reason; keep old qualified release available. No silent fallback to fabricated LLM output.
•  Never share one candidate’s private resume, personal history or employer correspondence with other customers or publish it into a reusable Template without explicit reviewed approval and sanitization.
OUT OF SCOPE: fine-tuning model weights; auto-apply or send email; scraping LinkedIn/boards or bypassing site terms; job guarantee; generalized multi-agent framework; voice/video agents; recruiter CRM; new IAM system; Kubernetes; a separate universal Chat UI; large Template marketplace; unlimited autonomous self-training.
11. Deliverables and definition of DONE
At H6 the developer submits: live Factory SPA URL, live CS Job-Seeker runtime in the SOW016 Office, one-command instantiation instructions, committed sources and OpenAPI, fully pinned T0/T1/T2+Skill+knowledge records, two qualified T2 versions, SHA-256 release manifest, all PASS/FAIL evidence, two-person DOGFOOD.md, operating/runbook instructions, and exact Git SHA.
DONE =  An actual SAFI tester uses a genuine model-backed Job-Seeker Agent in the customer-owned Office, the Trainer refines and qualifies the Template, a newly born Agent inherits the lesson, an older Agent stays unchanged, and ALL acceptance tests pass by Hour 6.
