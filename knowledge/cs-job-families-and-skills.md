# Entry-level computer science job families and the skills they ask for

This guide is written by SAFI as general orientation for new computer science graduates. It describes common kinds of entry-level work and the skills postings usually mention. It makes no claims about salaries, hiring rates or how many jobs exist; for any specific job, the posting itself is the only authority on what that employer wants.

## How to read a job family

A job title is a label, and employers use labels differently. Two postings titled "Junior Developer" can describe quite different work. Treat the families below as starting points, then read the responsibilities and requirements in each posting on their own terms.

## Software engineering (entry level)

Typical work: building and fixing features in an existing codebase, writing tests, reviewing code with teammates, reading unfamiliar code and learning a team's tools.

Skills postings often mention:
- A general-purpose language such as Python, Java, JavaScript or TypeScript, C#, or Go.
- Data structures and algorithms at a practical level: arrays, hash maps, trees, sorting, and reasoning about running time.
- Version control with Git, including branches and pull requests.
- Basic web or service concepts: HTTP, APIs, JSON, databases and SQL.
- Testing habits and the ability to read an error message and debug.
- Clear written communication, since much of the job is explaining changes to others.

## Quality assurance and test engineering (entry level)

Typical work: checking that software behaves as intended, writing test cases and automated tests, reproducing and reporting defects precisely, and helping a team decide whether something is ready to release.

Skills postings often mention:
- Careful reading of requirements and spotting what is unclear or missing.
- Writing test cases, including edge cases and failure cases.
- Scripting in a language such as Python or JavaScript to automate checks.
- Familiarity with a test framework, and with API or browser testing tools.
- Writing a bug report that someone else can reproduce from your description.

## Data roles (entry level)

Typical work: collecting, cleaning and summarising data, building reports or dashboards, answering questions with queries, and explaining results to people who are not technical.

Skills postings often mention:
- SQL for filtering, joining and aggregating data.
- A scripting language, commonly Python or R, and its data libraries.
- Spreadsheets and a charting or dashboard tool.
- Basic statistics: averages, distributions, and knowing when a result might be misleading.
- Communicating a finding in plain language with an honest note about its limits.

## Skills that cross all three families

Reading and writing clearly, learning quickly from documentation, asking good questions, finishing small things reliably, and being honest about what you do and do not know. These matter because entry-level roles expect you to learn on the job.

## Showing skills through academic projects

New graduates often have little paid experience, and that is normal. Class projects, a capstone, research work and personal projects are legitimate evidence of skills when described honestly. A useful description says what the project was, what you personally built or decided, which tools you used, and what the outcome was. Label academic work as academic. Do not give a class project a job title, and do not describe it as employment. Specifics such as "implemented the search feature and wrote its unit tests" are more convincing than general claims such as "strong programmer".

## Reading a posting for requirements

Separate what the posting says it requires from what it merely prefers. Note the exact words used. If a requirement is unclear, record it as unknown rather than guessing. A gap between your evidence and a requirement is useful information: it tells you what to learn, build, or be ready to discuss honestly.

## Limits of this document

This is general orientation written on 2026-11-03. It does not describe any particular employer, and it does not describe the current job market. Check each posting directly.
